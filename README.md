# Companies data pipeline

Загрузка каталога компаний из постраничной JSON-выгрузки (`data/page_001.json` …
`page_020.json`) в PostgreSQL и три аналитических запроса поверх неё (задачи 1–2).

Отдельно (задача 3) — загрузка `review.csv`, "свежей выгрузки" для той же БД,
которая на поверку оказалась не отзывами, а ещё одной порцией компаний с
рядом проблем в данных. Полный разбор — в [`ANOMALIES.md`](./ANOMALIES.md).

## Данные

Каждый `page_XXX.json` — объект вида:

```json
{
  "page": 1,
  "per_page": 50,
  "total": 1000,
  "items": [
    {
      "id": "c_000001",
      "name": "ООО «Прайм Медиа»",
      "category": "Типография",
      "city": "Челябинск",
      "address": "ул. Южная, д. 96",
      "rating": 4.1,
      "reviews_count": 191,
      "site": null,
      "phone": "+7 (495) 248-44-40"
    }
  ]
}
```

20 страниц × 50 записей = 1000 записей, пагинация (`page`/`total`) консистентна
по всем файлам. В сырых данных 6 полных дублей (одинаковые `id` и все
остальные поля) — после дедупликации 994 уникальные компании.
`rating` и `site`/`phone` могут быть `NULL`.

## Схема БД

`schema.sql`:

- `categories(id, name)` — справочник категорий (22 значения)
- `cities(id, name)` — справочник городов (20 значений)
- `companies(id, name, category_id, city_id, address, rating, reviews_count, site, phone, loaded_at)`
  — основная таблица, `id` из исходных данных используется как PRIMARY KEY

Дедупликация — на двух уровнях:
1. `PRIMARY KEY (id)` + `ON CONFLICT (id) DO UPDATE` в `load.py`: повторная
   загрузка того же `id` обновит запись, а не создаст дубль.
2. `UNIQUE (name, city_id, address)` — страховка на случай, если одна и та же
   компания попадётся под разными `id`.

Индексы: `category_id`, `city_id`, `reviews_count` — под запросы из
`queries.sql`, плюс частичный индекс по `category_id WHERE site IS NOT NULL`
для запроса про долю компаний с сайтом.

## Запуск

### 1. Поднять Postgres

```bash
docker compose up -d
```

Схема (`schema.sql`) применится автоматически при первом старте контейнера
(через `docker-entrypoint-initdb.d`). Postgres слушает `localhost:5432`,
база/юзер/пароль — `companies`/`companies`/`companies` (см. `.env.example`).

### 2. Загрузить данные

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python load.py --data-dir ./data --dsn "postgresql://companies:companies@localhost:5432/companies"
```

Скрипт идемпотентен — его можно запускать повторно (например, при появлении
новых страниц), дубли не создаются.

### 3. Выполнить аналитические запросы

```bash
docker exec -i companies_db psql -U companies -d companies < queries.sql
```

или через любой psql-клиент, подключившись по DSN из `.env.example`.

## Задача 3: review.csv

`review.csv` называется "отзывы", но по факту содержит компании в той же
схеме, что и `page_*.json` — и заметно грязнее по качеству. Полный разбор
всех найденных проблем и как каждая обнаружена — в
[`ANOMALIES.md`](./ANOMALIES.md). Коротко: точные дубли строк, 5 разных
написаний одного и того же города (включая битую кодировку), одна строка со
сдвигом колонок (потеряна категория), рейтинги вне диапазона 0–5 и не-числа,
отрицательные/дробные/текстовые `reviews_count`, пара сломанных
телефонов/сайтов.

### Запуск

```bash
python load_review.py --data-dir ./data --csv ./data/review.csv \
  --dsn "postgresql://companies:companies@localhost:5432/companies"
```

(Предполагается, что `docker compose up -d` и загрузка из задачи 1 уже
выполнены — `load_review.py` дописывает данные в ту же БД.)

Скрипт печатает в консоль список всех сработавших аномалий и сохраняет их
же в `review_anomalies_raw.txt` рядом с собой — это сырой лог для аудита,
`ANOMALIES.md` — его читаемый разбор с объяснениями.

### Короткий отчёт по данным

Из 205 непустых строк `review.csv`:

| | |
|---|---:|
| Точных дублей строк (пропущены) | 3 |
| Невосстановимых строк — потеряна категория (пропущена) | 1 |
| **Успешно загружено** | **201** |
| Из них — новые компании (id вне диапазона `page_*.json`) | 195 |
| Из них — уже встречались в `page_*.json` (данные идентичны) | 6 |
| Точечных аномалий в значениях полей (см. `ANOMALIES.md`) | 15 |
| Уникальных городов после нормализации | 20 (совпадает со справочником из задачи 1) |
| Уникальных категорий | 22 (совпадает со справочником из задачи 1) |
| Доля компаний с сайтом | 71.6% (144 из 201) |
| Средний рейтинг (по непустым значениям, 180 из 201) | 4.26 |

Ни одна из 22 категорий и ни один из 20 городов, встретившихся в `review.csv`,
не оказались за пределами справочников, построенных на `page_*.json` — после
нормализации написания городов датасет полностью совместим с основным.

## Примечания / что можно улучшить дальше

- Для по-настоящему больших выгрузок `load.py` стоит переписать на
  батчевую вставку с `COPY` вместо `execute_values`.
- Сейчас справочники (`categories`, `cities`) наполняются "на лету" при
  каждой загрузке — для продакшена их можно вынести в отдельную миграцию.
- Логика дедупликации рассчитана на точные дубли; для fuzzy-дедупликации
  (опечатки в названии/адресе) потребуется отдельный шаг с нормализацией
  строк или триграммным сравнением (`pg_trgm`).
